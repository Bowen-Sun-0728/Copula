    Compare, repeat and sweep¶

    Which runs share samples is decided by their coordinates: names and values Copula reads from the command line (--variant strict, seed=1), from --set k=v and from framework adapters. Each name has a class (Runs, coordinates and versions):

    • compare: what you are comparing (variant, prompt, config, candidate, ...). Runs that differ in it share samples.
    • replicate: an index of independent repeats (seed, trial, rep, ...). Runs that differ in it never share. Every name Copula does not know is a replicate, the safe direction.
    • case: the input (case, example, task_id, ...). Runs that differ in it never share.
    • annotation: recorded and ignored (output_dir, log_dir, run_name, ...).

    --compare NAME, --replicate NAME, --case NAME and --annotation NAME set the class of a name; the built-in names are listed in Coordinate names and recipes.

    The examples on this page use this agent:

    agent.py
    import argparse

from openai import OpenAI

CHECKS = {
    "short": "Check the answer. Reply OK, or give a corrected answer.",
    "strict": "Check every claim in the answer. Reply OK only if all are correct.",
}
parser = argparse.ArgumentParser()
parser.add_argument("--variant", default="short", choices=CHECKS)
parser.add_argument("--seed", type=int, default=0)
args = parser.parse_args()
client = OpenAI()


def ask(system, user):
    r = client.chat.completions.create(
        model="Qwen/Qwen2.5-7B-Instruct", temperature=0.7,
        messages=[{"role": "system", "content": system}, {"role": "user", "content": user}])
    return r.choices[0].message.content


for q in ["Why is the sky blue?", "What is a prime number?", "Who wrote Hamlet?"]:
    answer = ask("Answer the question in one sentence.", q)
    verdict = ask(CHECKS[args.variant], f"Q: {q}\nA: {answer}")
    print(f"{answer}  {verdict}")

This is what an A/B test or a regression check of an agent wants: each variant sees samples distributed as it would alone, and the pair shares what it can.

    Repeated calls inside a run¶

    A run that sends the same request several times gets a new sample each time: the k-th identical request of a run reads the k-th sample of its group. Repeats inside a run are independent, as they are without Copula.

    vote.py
    import sys
from collections import Counter

from openai import OpenAI

client = OpenAI()
n = int(sys.argv[1].split("=")[1])            # n=3
votes = Counter()
for _ in range(n):
    r = client.chat.completions.create(
        model="Qwen/Qwen2.5-7B-Instruct", temperature=1.0,
        messages=[{"role": "user", "content": "Is 91 a prime? Answer yes or no."}])
    votes[r.choices[0].message.content] += 1
print(len(votes), "distinct answers")

    Larger budgets read the samples of smaller ones when the budget is a compare coordinate. n is not a built-in name, so --compare n says that runs with different n are compared:

    Sweeps¶

    A sweep over a parameter compares its values within each seed:

    $ for lr in 1e-4 3e-4 1e-3; do
>   copula run --exp sweep --compare lr -- python train_agent.py --lr $lr --seed 1
> done

    Unknown names are replicates, so without --compare lr every value of lr would be generated from scratch: correct, only more expensive. To run the sweep in parallel, start one server for the project first.

    In a Slurm array, SLURM_ARRAY_TASK_ID becomes a replicate coordinate of every run on its own.

    Final numbers: the holdout phase¶

    Runs that reuse samples are compared on the same draws, which is what you want while developing. A version chosen because it did well on some samples is optimistic when it is scored on those same samples. Score the final choice in the holdout phase, whose sampled calls share nothing with the search phase:

    $ copula run --exp ab --phase holdout -- python agent.py --variant strict --split test

    Inside one process, copula.holdout() does the same for a block of code (Prompt and harness optimizers).

    Seeds in requests¶

    A seed in the request body is a stream of its own: the requests with seed=7 share samples with other seed=7 requests of the group, and the k-th identical seeded request of a run reads the k-th sample of that stream. Copula does not send the client's seed to the model server (Seeds).
